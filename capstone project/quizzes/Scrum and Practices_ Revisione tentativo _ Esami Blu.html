What are the key benefits of having an Automated Build system? (Select all that apply)

Domanda 1 Scegli una o più alternative:

Ensures a consistent and repeatable build process.

Correct. This eliminates "it works on my machine" problems by building in a clean, standard environment every time.

It is the foundation for Continuous Integration (CI).

Correct. You cannot have CI (integrating code frequently) without an automated build to validate those integrations.

It reduces the need for a version control system.

It eliminates all bugs from the code.

Provides fast feedback on integration errors and failing tests.

Correct. This is the primary benefit. Developers find out about problems in minutes, not days.

Feedback

Your answer is correct.

Benefits include fast feedback (knowing in minutes if a change broke something), consistency (the build is always done the same way, removing "it works on my machine" errors), and it is the foundational practice that enables Continuous Integration.

Le risposte corrette sono: Provides fast feedback on integration errors and failing tests., Ensures a consistent and repeatable build process., It is the foundation for Continuous Integration (CI).

What are the key benefits of Collective Ownership? (Select all that apply)

Domanda 2 Scegli una o più alternative:

It ensures that only the original author can introduce new bugs to a module.

It reduces knowledge silos and bottlenecks.

Correct. The team is no longer dependent on a single expert for a specific part of the system.

It creates clear individual accountability for bugs.

It improves code quality by having more people review and refactor it.

Correct. More eyes on the code lead to better design and adherence to standards.

It increases the team's flexibility to respond to change.

Correct. Any available developer can pick up the next most important task, regardless of what part of the code it touches.

Feedback

Your answer is correct.

By allowing anyone to change any code, collective ownership spreads knowledge, reduces bottlenecks (no more waiting for the "one person" who knows a module), and increases team flexibility. It also tends to improve code quality as more people review and refactor it.

Le risposte corrette sono: It reduces knowledge silos and bottlenecks., It improves code quality by having more people review and refactor it., It increases the team's flexibility to respond to change.

Testo della domanda

Which of the following Agile practices directly support Collective Ownership? (Select all that apply)

Domanda 3 Scegli una o più alternative:

Continuous Integration

Correct. When many people are changing the same codebase, a CI system is essential to ensure their changes integrate correctly.

Refactoring

Correct. Collective ownership empowers any developer to refactor (improve) code they find, even if they didn't write it originally.

Individual performance bonuses

Pair Programming

Correct. Pairing is a primary mechanism for transferring knowledge, which is necessary for anyone to be able to work on any part of the code.

Manual deployment processes

Feedback

Your answer is correct.

Practices that spread knowledge and require team-wide standards are essential for collective ownership. Pair Programming (spreads knowledge), Refactoring (improving code anyone owns), and Continuous Integration (ensuring all code works together) are key enablers.

Le risposte corrette sono: Pair Programming, Refactoring, Continuous Integration

What is the main purpose of "Work in Progress" (WIP) limits on a Kanban board?

Domanda 4 Scegli un'alternativa:

To prevent bottlenecks and encourage a "pull" system by forcing the team to finish work before starting new work.

Correct. WIP limits are the mechanism that creates a "pull" system and exposes bottlenecks in the workflow.

To assign a specific number of tasks to each team member.

To ensure everyone on the team is always busy.

To track the total number of story points completed in a week.

Feedback

Your answer is correct.

WIP limits are a core feature of Kanban. By limiting the number of tasks in any given state (e.g., "In Progress"), the team is forced to finish work before starting new work. This prevents bottlenecks and improves the flow of value.

La risposta corretta è: To prevent bottlenecks and encourage a "pull" system by forcing the team to finish work before starting new work.

Product Backlog refinement is...

Domanda 6 Scegli una o più alternative:

Responsability of the whole team, though not everybody contributes in the same way.

Correct. All the team contributes to the Product Backlog refinement because everybody needs to fully understand what has to be developed.

Only done during the Sprint Planning meeting.

Done only by the Product Owner.

An ongoing activity of adding detail, estimates, and order to Product Backlog items.

Correct. This is the definition of refinement.

Feedback

Your answer is correct.

Product Backlog refinement is the act of adding detail, estimates, and order to items in the Product Backlog. It is an ongoing activity to refine items so they are "Ready" for Sprint Planning. It is not an official event, but a necessary activity.

Le risposte corrette sono: An ongoing activity of adding detail, estimates, and order to Product Backlog items., Responsability of the whole team, though not everybody contributes in the same way.

Who is responsible for managing the Product Backlog? (Select all that apply)

Domanda 7 Scegli una o più alternative:

The Testers

Incorrect. Stakeholders provide input and feedback, but they do not manage the backlog.

Testo della domanda

What information is typically visible on a task card on a Task Board? (Select all that apply)

Domanda 15 Scegli una o più alternative:

The full list of stakeholder sign-offs

Incorrect. This level of administrative detail is generally not kept on the Task Board, which is a fast-moving, tactical tool for the Developers.

An estimate of remaining effort (e.g., hours)

Correct. This is very common on Scrum Task Boards, as it helps the team track progress towards their Sprint Goal (often via a burndown chart).

The person or pair currently working on it

Correct. This makes it clear who to talk to about the task and shows what everyone is focused on.

A brief description of the task

The Product Goal

Incorrect. The Product Goal is the high-level, long-term objective. The *Sprint Goal* is relevant, but the Product Goal itself is too broad for a single task card.

Feedback

Your answer is incorrect.

A task card should contain just enough information to be useful. This usually includes a clear description of the task, who is currently working on it (the assignee), and often an estimate of the remaining effort (like hours).

Le risposte corrette sono: A brief description of the task, The person or pair currently working on it, An estimate of remaining effort (e.g., hours)
